# Агент-археолог

Исследует каталог с кодом, сравнивает размеры модулей и объясняет их назначение.
Использует существующую настройку модели из `.env`: `MODEL_NAME`, ключ провайдера
и при необходимости `MODEL_BASE_URL` (для шлюза также нужен `OPENAI_API_KEY`).

```bash
uv sync
uv run project ./src
uv run project ./src "Какие модули здесь самые большие и что в них происходит?"
```

В конце выводятся три блока: итоговые задачи (список может быть пустым),
последовательность вызовов инструментов и ответ. В блоке инструментов также
видны сообщения `status=error` и число реальных запусков `module_report`
по каждому файлу. Внутренние retry не добавляют новых вызовов модели в историю.

`module_report` первый раз для каждого файла выбрасывает `ConnectionError`.
В обычном порядке `[ToolErrorMiddleware, ToolRetryMiddleware]` retry выполняет
второй запуск: небольшой файл возвращает число строк и код, файл длиннее
1000 строк даёт `ValueError` с размером и подсказкой использовать `grep_search`.
Этот `ValueError` не повторяется. Поиск работает средствами Python без ripgrep.

Для сравнения порядка middleware:

```bash
uv run project ./src --reverse-middleware
```

В этом режиме обработчик перехватывает первый сбой до retry: один запуск на
файл и сообщение о недоступном хранилище. Счётчики сбрасываются при создании
агента. Решения о плане и дальнейших вызовах принимает модель.

Проверки с временными файлами (включая файл на 1001 строку и пустой каталог),
без ключей API и сетевых обращений:

```bash
uv run python -m unittest discover -s tests -v
```
